# RazorGuard — ML Pipeline Documentation

## Overview

The ML pipeline detects fraudulent payment transactions using supervised classification models trained on synthetic transaction data. All metrics are calculated dynamically — nothing is hardcoded.

## Dataset

- **Source**: `data/transactions.csv` generated by `scripts/generate_demo_data.py`
- **Size**: ~20,000 transactions
- **Fraud Rate**: ~3.13% (imbalanced)
- **Features**: 18 columns including behavioral, velocity, and contextual signals

## Pipeline Stages

### 1. Data Validation (`ml/data.py`)
- Validates required columns, null values, positive amounts, binary target, unique IDs, valid timestamps
- Raises `ValueError` on any data quality failure

### 2. Chronological Data Split (`ml/train.py`)
- Data sorted by timestamp (prevents future information leakage)
- **70% Training** / **15% Validation** / **15% Held-out Test**
- Validation used for model selection and threshold optimization
- Held-out test used ONLY for final locked evaluation

### 3. Feature Engineering (`ml/features.py`)
- **Numerical Features**: amount, account age, historical counts, failure rates, velocity counts, time deltas, amount deviations
- **Categorical Features**: payment method (one-hot encoded)
- **Binary Features**: new_device, unusual_country, payment_method_change, country_change, unusual_transaction_hour
- **Leakage Prevention**: All expanding/rolling windows use `shift(1)` to exclude the current transaction

### 4. Model Training (`ml/train.py`)
- **Logistic Regression**: Baseline model with balanced class weights
- **Random Forest**: Primary classifier with balanced class weights
- **Isolation Forest**: Unsupervised anomaly detector trained on legitimate transactions only

### 5. Model Selection
- Models compared on **validation set** using PR-AUC (best for imbalanced classification)
- Best model selected automatically

### 6. Threshold Optimization (`ml/threshold.py`)
- Evaluates thresholds 0.1–0.9 on validation data
- Uses business cost model: FP Cost = count × ₹50, FN Cost = sum of missed fraud amounts
- Selects threshold minimizing total expected loss
- **Note**: All cost assumptions are synthetic/illustrative

### 7. Final Evaluation
- Locked model + threshold evaluated on held-out test set
- Full metrics calculated: accuracy, precision, recall, F1, ROC-AUC, PR-AUC, confusion matrix, business costs

### 8. Prediction (`ml/predict.py`)
- Loads saved artifacts (model, preprocessor, metadata)
- Accepts single transaction dictionaries
- Returns fraud probability, risk level (LOW/MEDIUM/HIGH/CRITICAL), and threshold

## Limitations

- Dataset is **synthetic** — patterns may not reflect real-world fraud
- Cost assumptions (₹50 FP cost) are illustrative, not Razorpay's actual costs
- Models are not calibrated for probability estimation
- No online learning or concept drift detection
