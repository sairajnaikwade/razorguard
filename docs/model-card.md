# RazorGuard — Model Card

## Model Details

- **Model Name**: Random Forest Classifier (RandomForestWrapper)
- **Version**: 1.0
- **Type**: Binary Classification (Fraud / Legitimate)
- **Framework**: scikit-learn
- **Training Date**: 2026-08-24

## Intended Use

- **Primary Use**: Score payment transactions for fraud risk
- **Users**: Fraud analysts, risk managers, automated flagging systems
- **Out of Scope**: Real-time production deployment without proper calibration and monitoring

## Training Data

- **Source**: Synthetic dataset generated by `scripts/generate_demo_data.py`
- **Size**: ~20,000 transactions
- **Fraud Rate**: ~3.13%
- **Split**: 70% train (14,000) / 15% validation (3,000) / 15% held-out test (3,000) (chronological)
- **Important**: This is synthetic data. Real-world fraud patterns may differ significantly.

## Features

The model uses the following 24 features engineered from transaction and history records:
- **Numerical Features (12)**:
  - `amount`: Current transaction amount
  - `customer_account_age`: Account age in days
  - `historical_transaction_count`: Number of prior transactions
  - `historical_failure_count`: Number of prior transaction failures
  - `historical_failure_rate`: Ratio of failed transactions to total transactions
  - `failed_attempts`: Number of failed attempts immediately preceding transaction
  - `transactions_last_5m`: Rolling transaction count in the past 5 minutes (excluding current)
  - `transactions_last_1h`: Rolling transaction count in the past 1 hour (excluding current)
  - `amount_last_1h`: Rolling transaction amount sum in the past 1 hour (excluding current)
  - `time_since_previous_transaction`: Seconds elapsed since previous transaction
  - `amount_vs_customer_average`: Ratio of current amount to customer's historical average
  - `amount_deviation`: Deviation of amount from customer's average in units of stddev
- **Categorical & Binary Features (12)**:
  - `pm_UPI`, `pm_card`, `pm_netbanking`: Payment method (one-hot encoded)
  - `new_device`: 1 if device ID is newly seen for customer, 0 otherwise
  - `unusual_country`: 1 if country differs from customer's standard, 0 otherwise
  - `payment_method_change`: 1 if payment method differs from customer's prior, 0 otherwise
  - `country_change`: 1 if country differs from customer's previous transaction, 0 otherwise
  - `unusual_transaction_hour`: 1 if transaction hour is between 00:00 and 05:00, 0 otherwise

## Confusion Matrix

- **True Negatives (TN)**: 2,903 (legitimate classified as legitimate)
- **False Positives (FP)**: 3 (legitimate classified as fraud)
- **False Negatives (FN)**: 0 (fraud classified as legitimate)
- **True Positives (TP)**: 94 (fraud classified as fraud)

## Threshold Selection

- **Method**: Business cost minimization on validation data (cost curve optimization)
- **FP Unit Cost**: ₹50 (synthetic assumption — analyst review overhead)
- **FN Cost**: Transaction amount (direct financial loss of missed fraud)
- **Selected Threshold**: 0.30
- **Expected Business Cost on Held-out Test**: ₹150.00 (3 FPs * ₹50, 0 FNs * amount)

## Ethical Considerations

- Model trained on synthetic data with artificially injected fraud patterns
- No real customer data used
- Cost assumptions are illustrative, not based on actual business data
- Model should not be deployed to production without extensive validation on real data

## Limitations

- Synthetic data may not capture real-world fraud complexity
- No concept drift detection or online learning
- Limited to tabular features (no text, image, or graph-based signals)
- Not calibrated for probability estimation
- Single-model approach (no ensemble or stacking)

## Caveats and Recommendations

- Retrain on real data before any production deployment
- Implement model monitoring for performance degradation
- Regularly update threshold based on changing fraud patterns
- Consider ensemble methods for improved robustness
